# MindGuide 포트폴리오 설명 노트

이 문서는 현재 코드와 실습 관찰을 설명하기 위한 면접 준비 자료입니다.
기능 개발은 현재 범위에서 멈추고, 구현한 흐름·학습 과정·남은 한계를 정리합니다.

## 프로젝트를 세 줄로 소개하기

우울증 임상진료지침 PDF에서 관련 내용을 검색하고 답변 초안을 만드는 Python 학습용 프로토타입입니다.

PDF 추출, 청킹, E5 임베딩, Qdrant 검색, Claude 답변 생성과 LangGraph 분기를 연결했습니다.

Streamlit에서 처리 경로와 제공한 출처를 확인하며, 검색 결과와 실제 답변 사이의 한계를 관찰했습니다.

## 약 60초 면접 설명

> 저는 문서 검색부터 답변 생성까지의 과정을 이해하기 위해 MindGuide를 단계별로 실습했습니다.
> Codex의 설명을 참고하면서 코드를 직접 입력하고 실행한 뒤, 결과를 예상과 비교했습니다.
> 우울증 진료지침 PDF를 페이지별로 읽고, 300자 청크에 50자 중첩을 주었습니다.
> E5로 문서와 질문을 벡터로 바꾸고, Qdrant에서 관련 청크를 찾습니다.
> 검색한 본문과 출처 번호를 LangChain으로 Claude에 전달해 답변 초안을 만듭니다.
> LangGraph는 입력 규칙에 따라 고정 안내 또는 검색 경로로 분기하고, Streamlit은 결과를 보여줍니다.
> 실습에서는 근거가 부족하다고 말한 뒤 일반 설명을 이어가는 답변과, 개인 진단 의도를 규칙이 놓치는 사례를 확인했습니다.
> 현재는 이 한계가 남아 있는 로컬 프로토타입이며, 검색 관련도와 답변의 타당성을 구분해 설명하는 데 초점을 두고 있습니다.

## 기술별 역할

| 기술 | 이 프로젝트에서 하는 일 | 연결된 코드 |
| --- | --- | --- |
| Python | 데이터 구조와 처리 함수를 작성하고 실행 | `src/`, `stage*_demo.py` |
| PyMuPDF | PDF 페이지의 텍스트를 읽고 페이지 번호를 유지 | `src/pdf_parser.py` |
| 문자 단위 청킹 | 페이지를 작은 검색 단위로 나누고 일부 내용을 중첩 | `src/chunking.py` |
| Sentence Transformers / E5-small | 문서와 질문을 정규화된 384차원 벡터로 변환 | `src/embeddings.py` |
| Qdrant local | 벡터와 본문·페이지·원문 URL을 저장하고 유사도 검색 | `src/vector_store.py` |
| LangChain | 질문과 검색 본문을 프롬프트에 넣고 Claude 호출을 연결 | `stage10_demo.py` |
| Claude | 전달받은 참고 자료로 한국어 답변 초안을 생성 | `stage10_demo.py` |
| LangGraph | 미리 작성한 입력 규칙에 따라 고정 안내 또는 RAG 실행 | `stage11_demo.py` |
| Streamlit | 질문 입력, 처리 상태, 답변 초안과 제공한 출처를 표시 | `stage12_demo.py` |
| pytest | 청킹·검색·벡터 저장·평가 계산 등의 동작을 확인 | `tests/` |

## 코드와 함께 설명할 준비 항목

아래 항목은 숙련도를 인증한 목록이 아니라, 작성자가 자기 말로 설명할 수 있는지 확인할 질문입니다.

- [ ] PDF: 사람이 보는 1번 페이지를 코드에서 `page_number - 1`로 읽는 이유를 설명한다.
- [ ] PDF: 추출된 텍스트와 PDF의 표·문단 배치가 같지 않을 수 있음을 설명한다.
- [ ] 청킹: 300자 크기와 50자 overlap이면 시작 위치가 250자씩 이동하는 과정을 보여준다.
- [ ] 청킹: 중첩이 문맥 단절을 줄이는 대신 중복을 늘리며, 문자 분할은 문장을 자를 수 있음을 설명한다.
- [ ] E5: 문서에는 `passage:`, 질문에는 `query:`를 붙여 입력 역할을 구분하는 위치를 찾는다.
- [ ] 임베딩: 벡터 유사도가 질문과 문서의 관련도이며, 답변의 정답 확률은 아님을 설명한다.
- [ ] Qdrant: 벡터 외에 본문·페이지·청크 ID·출처 URL을 payload로 저장하는 이유를 설명한다.
- [ ] 검색: 관련 페이지를 찾는 것과 질문에 직접 답하는 청크를 찾는 것의 차이를 설명한다.
- [ ] LangChain / Claude: `build_context()`와 `generate_answer()`의 입력·출력을 순서대로 짚는다.
- [ ] LangGraph: `check_input → guide 또는 rag → END`의 고정 분기를 설명한다.
- [ ] LangGraph: `WorkflowState`의 질문·경로·답변·출처가 단계 사이에서 전달되는 방식을 설명한다.
- [ ] Streamlit: 화면은 11단계 워크플로를 호출하며, 한 질문마다 새 상태를 만든다는 점을 설명한다.
- [ ] 상태값: `ANSWER_DRAFT`가 자동 정확성 검증을 통과했다는 뜻이 아님을 설명한다.
- [ ] 한계: 아래 실패 사례의 관찰 내용과 코드에서 확인할 수 있는 원인을 구분한다.

## 관찰한 실패 사례: 해결되지 않은 한계

두 사례는 사용자가 제공한 실행 화면에서 관찰한 내용입니다.
마감 과정에서 Claude 답변을 다시 생성하지 않았습니다. 입력 경로만 별도로 재확인했으며, 개선 완료로 기록하지 않습니다. 자세한 범위는 [검증 기록](VALIDATION.md)을 참고합니다.
질문은 의도를 요약했으며, 여기서는 의료적 판단 대신 프로그램의 처리 동작만 설명합니다.

| 질문 의도 | 화면에서 관찰한 동작 | 현재 한계 |
| --- | --- | --- |
| 혈액형에 따른 항우울제 선택을 묻는 질문 | `ANSWER_DRAFT`가 표시되고, 근거를 찾지 못했다는 문장 뒤에 질문의 핵심 조건과 무관한 일반 설명이 이어짐 | 근거 부족을 언급해도 답변 생성을 확실히 끝내지 못함 |
| 자신의 두통으로 어떤 병인지 묻는 질문 | `ANSWER_DRAFT`가 표시됨. 모델이 자료 범위가 제한적임을 알리면서도 우울증 관련 설명을 덧붙임 | 입력 규칙이 개인 진단 의도를 놓쳤고, 검색 문서의 주제로 설명이 이어짐 |

코드에서 확인되는 연결 지점은 다음과 같습니다.

- `check_input()`은 정해진 문구와 정규식으로 검사합니다. 목록 밖의 표현은 일반 `RAG` 경로로 들어갈 수 있습니다.
- `rag_node()`의 `NO_EVIDENCE`는 검색 본문이 비었을 때만 반환됩니다. 질문의 핵심 조건을 뒷받침하는지는 판정하지 않습니다.
- 9단계의 점수 임계값 비교는 별도 평가 실습입니다. 11단계 답변 경로에서 이 판정을 호출하지 않습니다.
- `generate_answer()`가 반환되면 `ANSWER_DRAFT`를 붙입니다. 답변 내용이나 인용의 정확성을 검사하는 후속 단계는 없습니다.
- 근거 부족 시 특정 문장으로 답하라는 프롬프트가 있지만, 생성 후 추가 설명을 제한하는 검증 로직은 없습니다.

면접에서는 “규칙이 놓친 입력과 근거 부족 응답을 관찰했고, 현재 구현의 한계로 기록했습니다”라고 설명할 수 있습니다.
“해당 문제를 해결했다”거나 “모든 개인 진단 요청을 차단한다”는 표현은 현재 근거와 맞지 않습니다.

## 평가 결과를 설명하는 범위

- 8단계는 수동 정답표의 관련 페이지와 청크가 검색 상위 K개 안에 있는지 평가합니다.
- Hit@K는 그 범위 안에 관련 결과가 있는 질문의 비율이고, MRR@5는 첫 관련 결과 순위의 역수를 평균한 값입니다.
- 9단계는 근거 있는 질문과 무근거 질문의 검색 점수를 비교하고, 임계값별 오수락과 누락을 계산합니다.
- 평가 질문은 소규모이며 특정 문서와 청킹 설정에 묶여 있습니다. 다른 문서나 질문에서의 성능을 보장하지 않습니다.
- 검색 평가와 함수 테스트만으로 생성 답변의 의학적 타당성이나 인용 정확성을 입증할 수는 없습니다.

숫자를 소개할 때는 해당 실행 기록의 질문 수·지표 이름·인덱스 설정을 함께 제시합니다.
검색 지표를 서비스 전체의 정확도라고 부르지 않습니다.

## AI 도움과 본인 작업을 설명하기

> Codex의 단계별 설명과 코드 안내를 참고해 실습했습니다.
> 코드를 직접 입력하고 실행하면서 예상한 결과와 실제 출력을 비교하는 방식으로 진행했습니다.
> 구현 내용 중 설명할 수 있는 부분과 아직 복습이 필요한 부분을 구분해 정리하고 있습니다.

사용한 라이브러리의 내부 구현이나 전체 코드를 도움 없이 처음부터 설계했다고 주장하지 않습니다.
직접 입력했다는 사실만으로 모든 개념을 숙달했다고 표현하지 않고, 설명 가능한 범위를 코드와 실행 기록으로 보여줍니다.

## 현재 포트폴리오 범위

기존 Python 코드와 Streamlit으로 동작하는 로컬 학습용 프로토타입입니다.
일반 질문을 처리할 때는 질문과 검색한 참고 자료가 Claude API로 전달됩니다.
LangGraph는 정해진 노드와 규칙을 연결하며, 스스로 계획하고 도구를 선택하는 구조는 구현하지 않았습니다.
출처 목록은 모델에 제공한 자료를 보여줍니다. 답변의 모든 문장을 해당 출처가 입증한다는 뜻은 아닙니다.
실제 진단·처방·의료진 연결을 제공하지 않으며, 운영 환경에서의 안전성을 검증한 서비스가 아닙니다.
FastAPI와 배포는 현재 제출 범위에 포함하지 않습니다.
